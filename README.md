# Wave：最小波形显示 Demo

Windows 原生 C++20 / Dear ImGui / ImPlot / DirectX 11。

只实现**批量接收数据、缓存、波形显示和交互**。不包含串口、RTT、网络、设备管理或通信协议。内置模拟信号只是测试数据的写入者，可直接替换。

## 运行

双击根目录的 `run.cmd`，或直接运行 `build/WaveDemo.exe`。程序自动开始产生测试数据，无需设备。

默认只有一个黑底波形窗口，以红色点和连线显示测试信号；坐标轴和网格保持简洁。顶部只有 `+ 窗口`、`信号`、`视图`、`?`。各窗口右上角只有小巧的 `Zoom` 入口，默认收起；不显示冻结、跟踪或自由状态文字。

- `+ 窗口` 添加波形窗口，窗口自动纵向平铺，最多 6 个。
- `信号` 或窗口内右键菜单选择要显示的通道；`视图` 中可按需显示性能信息。
- 左键平移、右键拖动和滚轮缩放保持当前跟随/暂停状态；实时跟随时最新数据始终位于右侧，包括按住左键或右键拖动的过程中。
- 在主波形区域左键双击，冻结当前整个显示缓冲区，所有窗口共用同一份数据，后台接收继续。
- 冻结期间可自由拖动两轴、围绕鼠标缩放、切换通道及查看整个缓存，数据不会被后台覆盖。再次双击，恢复显示缓冲区更新：跟踪窗口回到最新数据，自由窗口保留原视区，两轴尺度都保持不变。
- `Space` 与双击是同一操作，可交替使用；长按 Space 只切换一次。菜单栏不再提供冻结或实时按钮。
- 实时跟随时左键拖动可上下平移 Y 轴，时间轴持续追随最新数据；冻结或查看历史时可自由平移两轴。需要重新对齐当前数据时，可在右键或视图菜单中选择 `复位视图`。

| 操作 | 效果 |
| --- | --- |
| 按住右键向右拖 / 向左拖 | 连续放大 / 缩小 X 轴 |
| 按住右键向上拖 / 向下拖 | 连续放大 / 缩小 Y 轴 |
| 先按住 `Shift` / `Ctrl` 再右键拖动 | 只改变 X / Y 轴 |
| 右键单击 | 打开菜单；拖动结束不会弹出菜单 |
| 左键拖动 | 实时跟随时平移 Y 轴；暂停或查看历史时平移两轴 |
| 波形区域内滚轮 | 缩放时间轴；实时跟随时最新数据始终位于右侧 |
| 靠近左侧 Y 轴时滚轮 / `Ctrl` + 滚轮 | 只缩放 Y 轴，关闭 Y 轴自适应，保持时间轴跟随状态 |
| 波形区域内左键双击 / `Space` | 全部窗口冻结 / 恢复缓冲区更新；冻结时自由交互，恢复时保留两轴尺度 |
| 右上角 `Zoom` | 展开 / 收起当前窗口的整段缓存概览，关闭时保留主图范围 |

实时右键缩放时，X 轴围绕最新数据调整跨度，Y 轴以按下位置为锚点；暂停或查看历史时，两轴均以按下时的数据位置为锚点。可以斜向拖动同时调整两轴，拖回按下位置时恢复原来的尺度。缩放灵敏度为每移动 180 个逻辑像素，跨度变化 e 倍；右键移动 3 像素后进入缩放，滚轮使用同一缩放强度。

各窗口独立保存实时显示的时间跨度，滚轮调整后会持续生效；`视图 → 时间跨度` 只设置当前窗口。查看历史或冻结缓冲区时，滚轮围绕鼠标位置缩放，不会自动恢复实时跟随或缓冲区更新。Y 轴滚轮区域包含轴标签及坐标轴内侧 24 个逻辑像素。

双击和 Space 统一切换全局冻结状态，冻结后拖动和缩放都不会解除冻结。查看整个缓存的自由窗口恢复更新后若原区间已经过期，会保留视区并显示提示，可自行拖动或在右键菜单中复位视图。需要自动适配 Y 轴时，可启用 `Y 轴自适应` 或选择 `复位视图`。图例双击只操作图例，不会冻结或恢复缓冲区。

`Zoom` 概览显示整段缓存的时间范围，并用选框标出主图正在查看的区间。冻结或自由浏览时，拖动选框内部平移时间区间，拖动左右边缘调整跨度，点击框外可定位到该时间附近；概览内滚轮也只缩放时间轴。实时跟踪时，拖动左边界或点击概览调整时间跨度，右端始终保持最新数据，不自动冻结或改变其他窗口。要稳定检查某段历史，可先双击主波形冻结，再操作概览。

概览只控制 X 轴，不修改 Y 轴范围或自适应设置。很窄的选框会扩大显示和鼠标命中区域，但不放大实际数据跨度，精细缩放可继续用主图滚轮/右拖。预览仅绘制首个已选通道，并按概览像素宽度查询已有极值摘要；只在展开时查询，与主图共用当前数据池或冻结快照，不另复制缓存。概览内双击、右键和拖动不会同时触发主图的冻结、平移或菜单。

界面使用 Windows 自带微软雅黑。当前为 Windows x64 演示版本。

## 数据与性能设计

每通道 20,000 samples/s，8 通道，原始数据保留最近 30 秒。采样与显示独立，采样时间由样本序号决定。显示默认使用垂直同步，跟随窗口主要所在屏幕的当前刷新率，没有固定 60 FPS 限制；负载过高时实际帧率可能降低。将 GPU 排队限制为一帧以降低交互延迟，不支持时使用驱动默认值。最小化或被完全遮挡时暂停常规绘制。

| 通道 | 测试信号 |
| --- | --- |
| Phase A / B / C | 50 Hz、幅值 8 的三相正弦，相差 120° |
| PWM monitor | 1 kHz、35% 占空比方波，幅值 ±6 |
| Triangle | 15 Hz 三角波 |
| Modulated | 50 Hz 正弦，0.4 Hz 幅值调制 |
| Single-sample spikes | 50 Hz 正弦叠加相邻的单采样点正负尖峰，每秒一次 |
| Noise + ripple | 确定性伪随机噪声和 850 Hz 纹波 |

**20 kHz 是每通道采样率，不是屏幕刷新率，也不是模拟 PWM 的频率。**

数据池使用有界环形缓存，原始数值容量为 19.2 MB，另有极值摘要和容器开销。缩小时按查询区间分桶，保留每桶首点、最小值、最大值、末点并按时间排序，最多提交约 `4 × 绘图区宽度` 个点/曲线。摘要分层维护，避免每一帧扫描全部历史。放大后返回原始采样。

原始数据不因显示降采样而改变。冻结显示缓冲区通过复制当前缓存建立一份所有窗口共享的只读快照实现，后台 `DataStore` 仍正常接收和覆盖；恢复更新后释放快照并重新读取后台数据池，不回放冻结期间的数据。快照只在进入冻结时创建，不逐帧或逐窗口复制，内存占用会暂时上升；该操作适用于此 Demo 的小型缓存。当前没有长期录盘、导出或无限历史。

## 接入自己的数据

`src/wave_view.hpp` 是显示组件接口，`src/data_core.hpp` 是数据接收接口。显示组件不引用模拟信号源。

```cpp
#include "data_core.hpp"
#include "wave_view.hpp"

wave::DataStore data(20'000.0, 30.0, {
    {"Current", "A"}, {"Speed", "rpm"}
});
wave::WaveView view(data);

// 在你的接收线程中按批写入，每一帧包含所有通道：
// 第0帧 Current, Speed；第1帧 Current, Speed；...
std::vector<float> batch = {1.0f, 1000.0f, 1.1f, 1001.0f};
data.append(0, batch); // 第一个参数为该批首帧的绝对样本序号
// 下一批应从第2帧开始：data.append(2, next_batch);

// 在已经初始化 ImGui / ImPlot 的 GUI 帧循环里：
view.draw();
```

显示线程调用 `draw()`，后台线程可以同时 `append()`。数据池必须比显示组件活得更久。批次按“帧优先、通道交错”排列，数值必须有限，长度必须为通道数的整数倍；接口会复制数据，调用返回后调用者可以重用输入缓冲。

这个最小接口假设所有通道共用固定采样率、统一时间基准、按顺序写入。时间轴为 `sample_index / sample_rate`。样本序号不连续时，会清掉旧段并开始新的连续段，避免跨丢样区间连线；不支持不同采样率、乱序合并和多个独立时钟。后续可在此接口之外适配，不需要修改波形交互。

## 项目结构

```text
src/data_core.hpp/.cpp   接收接口、环形缓存、极值查询、暂停快照、测试信号源
src/wave_view.hpp/.cpp   波形显示组件；只读取数据池
src/plot_navigation.hpp  以按下位置为锚点的两轴连续缩放计算
src/overview_navigation.hpp 缓存概览选框移动、边缘缩放与范围约束
src/main.cpp            Windows 窗口、DX11、GUI帧循环、测试信号注入
tests/data_core_tests.cpp 缓存覆盖、尖峰、随机参考对照、快照、线程测试
tests/plot_navigation_tests.cpp 缩放方向、锚点、边界和极端输入测试
tests/view_interaction_tests.cpp 无原生窗口的真实 ImGui/ImPlot 鼠标交互测试
```

## 构建

已准备的本地微软编译工具可通过以下命令使用：

```powershell
powershell -ExecutionPolicy Bypass -File .\build-msvc.ps1
```

默认构建程序及三组测试，并运行全部测试。`-TestOnly` 仅构建/运行数据、缩放计算和波形交互测试，不创建原生窗口、不编译 Win32/DX11 后端；`-SkipTests` 仅构建程序。重建前关闭正在运行的 Demo。该便携环境只存放于项目 `.tools`，不修改系统环境变量。

已有 Visual Studio 2022（C++ 桌面开发工作负载）和 CMake 时，也可以使用：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\bootstrap.ps1 -SkipToolchain
cmake -S . -B build-cmake -A x64
cmake --build build-cmake --config Release
ctest --test-dir build-cmake -C Release --output-on-failure
```

也提供 `build.ps1` 和 `scripts/bootstrap.ps1` 的 LLVM-MinGW 路线；本机 Windows 应用控制阻止其无签名编译器，因此实际构建使用微软签名工具链。不要为本 Demo 关闭系统安全设置。

依赖固定为 ImGui `v1.92.9b-docking`、ImPlot `v1.0`。许可证和来源见 `THIRD_PARTY.md`。

## 验证

默认测试包含三部分：

- 数据层：环形缓存覆盖、正负单采样点尖峰、查询顺序/范围、随机批次与原始数组对照、冻结快照独立性，以及模拟源启动/停止。
- 缩放计算：拖动方向、固定锚点、单轴修饰键、分帧结果一致性、拖回原点、采样分辨率限制和极端输入。
- 交互集成：向真实 ImGui 队列注入鼠标和键盘事件，由真实 `WaveView` 和 ImPlot 帧循环验证左右键拖动期间持续跟随、实时左拖只平移 Y、冻结及历史模式下自由平移两轴、冻结时的缩放锚点、释放后不弹菜单、右键单击弹菜单、图例切换；还验证双击冻结所有窗口后自由检查数据、恢复时保留两轴尺度、实时滚轮缩放后跨度保持，以及 Y 轴滚轮分区。此测试不需要图形后端。

冻结交互还验证了后台环形缓存覆盖后冻结数据仍完整、冻结滚轮保留鼠标锚点、恢复更新后各窗口保留独立跟踪模式，以及长按 Space 不会重复切换。

实际窗口的短时运行检查：

```powershell
Start-Process -FilePath .\build\WaveDemo.exe -ArgumentList '--smoke-test' -WorkingDirectory .\build -Wait
Get-Content .\build\smoke-test.json
```

该模式运行约 12 秒，报告实际帧数、CPU 帧内耗时（不含等待垂直同步）、输入帧数、模拟源跳过帧数和每帧最大提交点数。它是当前机器上的短时检查，不能代表长期负载、真实设备传输或所有显卡的性能。
